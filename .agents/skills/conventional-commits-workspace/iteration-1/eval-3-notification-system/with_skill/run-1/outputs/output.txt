## Decision: split into multiple commits

These changes serve three different purposes: adding a feature, testing it, and documenting it. Per the Conventional Commits spec, each has its own type (`feat`, `test`, `docs`). Splitting keeps the history clean and makes changelogs/reverts easier.

If you prefer a single commit, replace the three commands below with:

```
git add -A && git commit -m "feat(notifications): add email notification system" -m "Introduce an email sending service powered by Nodemailer and a Bull job queue for asynchronous delivery. Includes unit tests and configuration documentation."
```
